# 固定残差究竟是什么

## 直接结论

当前“固定残差”是**基础均值路径＋可学习跨模态修正，修正系数固定为0.1**。固定的是一个乘法系数，不是网络参数，也不是预先固定的残差特征。

它是一项有机制解释的架构／优化设计选择，0.1本身是经验超参数。不能把它单独当作主要学术创新，或声称它从理论上保证双模态优于单模态。它是否提点需要看具体任务的匹配消融。

## 实际公式和代码

共同区域u中，g和p分别是已经过模态内质量归一化及位置／尺度编码的骨架和表面特征；m表示相应模态是否存在，缺失模态特征置零。

\[
b_u=\frac{g_u+p_u}{\max(1,m_u^g+m_u^p)},\qquad
h_u=b_u+0.1m_u^gm_u^pF_\theta([g_u,p_u]).
\]

双模态都在时，基础项是`(g+p)/2`；只有一路时，完整保留这一路；只有双模态同时存在时，交互MLP才提供修正。

```python
count = (has_g.to(graph.dtype) + has_p.to(graph.dtype)).clamp_min(1)
base = (graph + point) / count[:, None]
matched = has_g & has_p
delta = torch.zeros_like(base)
if matched.any():
    delta[matched] = joint(torch.cat((graph[matched], point[matched]), dim=-1))
x = base + 0.1 * delta
```

其中`joint`是`Linear(192,96) → GELU → Linear(96,96)`，即先拼接两个96维区域特征，再映射成96维修正。所有joint权重均可学习，监督梯度沿残差和基础路径共同反传。

“残差”指网络学习的加性特征修正，不是标签减预测值的误差，也不是attention归一化权重。0.1不是置信度、概率或验证集分数上的后处理。

## 为什么当时保留它

直接把两路特征交给MLP重建融合表示，可能同时改变已经有用的单模态信息。基础均值路径提供一个已有信息可直接传递的起点，交互分支学习补充或纠正。

固定系数还避免必须等待某个零初始化门控打开才开始使用交互分支。历史V26零起点门控在既定预算下没有超过该简单方案，因此保留固定系数。这个局部实验选择不能推出“所有门控方法都不如固定残差”。

0.1会缩放交互分支的输出和该路径的局部梯度，但不能简单等价为所有参数学习率变为十分之一：Adam、自适应统计和其余梯度路径使优化过程更复杂。

## 它是不是工程性的提点手段

**0.1这一取值主要属于工程超参数；保留证据再学习修正是常见架构原则；共同区域构造及双模态对应才是我们要论证的核心机制。**

还有一个重要限制：如果F最后一层没有幅值约束，它可以通过扩大权重抵消0.1。因此0.1不意味着残差始终只占主特征的10%，也不构成严格的稳定性保证。非零固定系数在表达能力上可被末层线性权重吸收，它更直接影响初始化、训练动态及正则化。

目前没有完整的残差系数扫描或与所有等容量残差形式的比较，不能声称0.1最优。full对mean_only删除了整个交互修正分支，只能支持“当前修正分支有贡献”，不能单独证明“固定0.1优于1.0、其他系数或所有可学习系数”。

## 论文表述建议

对外方法名可以使用“共同区域骨架—表面编码网络”等反映研究问题的名称。“固定残差完整模型”适合作为内部版本身份，不需要放在论文标题或作为第一创新。

方法正文可以写：在共同区域上分别归一化骨架和表面证据，保留其基础聚合路径，并通过小系数残差学习跨模态修正。随后说明该残差采用标准设计，主要贡献在共同支持域、异质测度处理、物理尺度表示及与层级传播的组合。

当前区域传播、上下文回写和FFN也有0.1残差系数；`mean_only`保留这些主干残差，仅删除跨模态joint修正。所以它不是“去掉所有残差”的实验。
